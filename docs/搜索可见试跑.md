# 搜索可见试跑：怎么跑、填什么、花多少、报告怎么看

2026-11-16 定的一次性试跑。只回答一个问题：**我们的帖子发出去三天，在它该被搜到的
那个词下面，前几页里到底看不看得见。** 看得见，才值得做成每天自动查；几乎都看不见，
按综合排序查排名就没有意义，得换办法。所以先花小钱试一次，现在不建任何自动的东西。

---

## 一、先记住这五句

1. **它不会自己跑。** 只有人手工敲 `python3 cli.py search-trial` 才会查。定时巡查
   （sweep / queue）、面板、部署文件都没有调它，合并这次改动不会多花一分钱。
2. **运营只做一件事：填 15 个「搜索关键词」格子。** 别的什么都不用勾、不用截图。
3. **整个试跑最多 280 次请求 / ¥20**，写死在代码里，每发一个请求之前先查账，
   再发会过线就停。计划是 185 次、约 ¥13。
4. **不往飞书写一个字。** 只读几列现成的。结果在跑命令那台机器的本地文件里。
5. **报告里只有计数。** 没有词、没有链接、没有笔记 ID、没有标题和昵称。词用
   K01、K02 这样的编号代替。

## 二、跑之前要准备的（一次）

| 谁 | 做什么 |
|---|---|
| 技术 / 负责人 | 在**登记表**里给要试的那几张表勾上 `搜索检查`。老的登记表没有这一列：在飞书里手工加一列同名的**复选框**就行（新建的登记表自带）。空着 = 关 |
| 技术 / 负责人 | 给这几张表建 `搜索关键词` 列：在面板「项目」里点这张表的「补齐缺的列」；或者在飞书里手工加一列同名的**文本**列（多选也认） |
| 运营 | 在这几张表里挑帖子，填 `搜索关键词`，**一共 15 个不同的词** |

没开 `搜索检查` 的表一切照旧：缺 `搜索关键词` 体检不报、点「补齐缺的列」也不会建它。
开了之后缺这一列，面板项目卡和 `doctor` 会说一句（巡查不受影响）。

没用登记表（只配了 `FEISHU_TABLES`）的部署没有这个开关：跑的时候用 `--table` 点名
要查哪几张表，点名就算开了；`搜索关键词` 列手工加。

### 运营怎么填

- **填在哪**：`搜索关键词` 那一格，和 `评论关键词` 不是一回事——那一列是「我们种的评论
  里有什么词」，这一列是「这一篇想在哪个词下面被搜到」。
- **一格一个词。** 写了几个只查第一个（多一个词多一份钱，上限装不下）。词前面带 `#` 没关系，会去掉。
- **一共 15 个不同的词，不能多。** 第 16 个词出现，命令直接拒跑、一分钱不花。
  同一个词填在几篇帖子上算一个词——建议每个词填 2 篇。大小写不同算同一个词。
- **挑哪些帖子**：小红书、发布 3 到 10 天、`发布时间` 填了的。评论多的、评论少的各挑一半。
- **试跑期间别改词。** 改了算新词，会占名额；删掉的词后面几轮查不了。
- 空着的行完全不查。别填整句话（超过 30 个字的不查）。

这些行不会被查，报告里会数出来有几行：不是小红书的、`巡查状态` 是「已失效」或
「疑似受限」的（搜不到是应该的）、短链展不开拿不到笔记 ID 的、`发布时间` 空着的
（算不出它发了几天，查了也进不了任何一档；不拿笔记 ID 去猜）。只被这种行带着的词
不占 15 个词的名额，也不花钱——把 `发布时间` 补上再跑就会查。

## 三、怎么跑

在装了这个仓库、配了 `.env` 的机器上跑（和巡查用同一份配置：`FEISHU_APP_ID` /
`FEISHU_APP_SECRET` / `FEISHU_REGISTRY` / `TIKHUB_API_KEY`，**不需要任何新的环境变量**）。
要隔天再跑一轮，所以用一台不会清家目录的机器，别用每次都是新容器的地方。

```bash
# 第一步：只演练。读表、数词、算要查几页、要花多少。不发任何付费请求，也不留文件。
python3 cli.py search-trial --dry-run

# 第二步：真跑第一轮（综合排序，每个词 3 页，最多 45 次，约 ¥3.24）
python3 cli.py search-trial
```

第一轮跑完就有那个问题的答案。后面几轮是为了知道名次稳不稳、能翻多深，
**要不要跑，看了第一轮的结果再定**：

| 命令 | 查什么 | 最多几次 | 约多少钱 |
|---|---|---|---|
| `python3 cli.py search-trial` | 综合排序，每个词 3 页 | 45 | ¥3.24 |
| `python3 cli.py search-trial --round latest` | 最新排序，每个词 2 页（看收没收录） | 30 | ¥2.16 |
| `python3 cli.py search-trial --round repeat1` | 隔一小时再查一遍 | 45 | ¥3.24 |
| `python3 cli.py search-trial --round repeat2` | 隔一天再查一遍 | 45 | ¥3.24 |
| `python3 cli.py search-trial --round depth` | 前两个词翻到第 10 页 | 20 | ¥1.44 |
| 合计 | | 185 | ¥13.32 |

其他参数：

- `--table A,B`：只查这几张表。
- `--report-only`：不查，只按已经拿到的页重新出一份报告。
- `--show-keywords`：在屏幕上列出 K01、K02 各是哪个词。只打在屏幕上，不进报告。
- `--state-dir 目录`：进度文件和报告放哪。默认 `~/.linkcheck/search-trial`。**不能放在仓库目录里**（会拒绝）。

### 中途断了、有几页没拿到

再跑**同一条命令**。拿到过的页直接用，不付第二次钱，只补没拿到的。命令最后会说
还差几页。有页没拿到时退出码是 1。

### 什么时候会自己停

- 账本到了 280 次或 ¥20：停，已经拿到的页照样出报告。
- Key 不对、余额不够、连不上：马上停。
- 被限流：等一下再试一次，还限流就停，过一会儿再跑。
- 某一页失败（比如 HTTP 400）：这个词后面的页先不翻，接着查下一个词。
- 第 1 页返回了条目、却一条笔记 ID 都认不出来：马上停（见第五节「读不懂的页」）。
- 另一个试跑正在跑：这次不跑。先拿到锁才读账本，所以两次不会各记各的账。

## 四、钱是怎么算的

- 单价：一页结果 = 一次请求 = $0.010 ≈ **¥0.072**（TikHub `app_v2/search_notes`，
  和一次评论查询同价；2026-11-16 对着对方公开的计价表核对）。走量折扣、每日免费额度对它都不生效。
- **账是往多了记的**：先记账再发请求；超时、限流、HTTP 400 的那几次都按花了钱算
  （失败的搜索页收不收钱还没验过）。读回答的时候断开、出错的也算——请求已经发出去了。
  只有**确定没发出去**（连都没连上）的那一次不算。
  所以真实账单只会比账本少，不会多。
- 账本记在进度文件里，分几次跑、隔天再跑都是同一本账。**别删进度文件**——删了账就清零了。
  文件坏了命令会拒跑，不会当成没花过钱重新开始。
- 按现在的单价，金额那个闸先到：277 次就是 ¥19.94，第 278 次不会发。
- 跑之前和跑之后各读一次 TikHub 余额（那个接口不收钱），差多少记在报告里，
  用来看失败的页到底收没收钱。巡查同时也在花这个余额，所以这个数只能当参考。
- 这笔钱不占巡查的预算（`MAX_YUAN_PER_RUN` 那一套管的是每轮巡查），巡查也不占它的。

## 五、报告怎么看

跑完屏幕上会打出来，同时存两份：`~/.linkcheck/search-trial/report.md`（给人看）
和 `report.json`（给机器读）。

**最上面那一句是答案**：发布 3 天内的帖子几篇，综合排序前 3 页里搜到几篇、没搜到几篇。

每一轮下面有三张表：

- **按帖龄**：3天内 / 4到7天 / 更早。帖龄是**查的那一刻**按表里的
  `发布时间` 算的，按日历日（发布当天算第 0 天）。（表上还留着一档「发布时间空」，
  正常是 0：这种行读表时就不收了。）
- **按评论数**：评论数够不够「评估中」门槛（默认 20 条），看评论少的帖子是不是更搜不到。
- **按词**：K01… 每个词拿到几页、看了前几位、它下面的帖子各落在哪一档。

每篇帖子落在这几档之一：

| 档 | 意思 |
|---|---|
| 前20 / 21到40 / 41到60 / 60以后 | 搜到了，排在第几位。名次只在自然结果里数 |
| 付费位 | 我们的帖子出现在像广告位的位置上，不算自然搜到 |
| 没搜到 | 该翻的页都翻了，里面没有。**只是说前几页里没有，不等于没被收录** |
| 没查全 | 有页没拿到，说不准。再跑一次补上 |

「看了前几位」是真数出来的，不是页数乘 20：一页有几条笔记是这次试跑要量的东西之一
（报告里有每页最少 / 中位 / 最多几条）。

其余几块：

- **名次稳不稳**：`repeat1` / `repeat2` 和第一轮比，同一篇帖子档位一样的几篇、变了的几篇、
  名次差超过 20 位的几篇、一次搜到一次没搜到的几篇。
- **结果条目的类型、键名**：对方返回的每条结果是什么类型、带哪些字段名（只有名字，没有内容）。
  用来认广告位到底是怎么标的——现在认广告位的规则是猜的，没实测过。
- **失败的页**：哪一轮、什么错、几次。
- **读不懂的页**：对方返回了条目、代码却一条笔记 ID 都认不出来（返回的样子和代码猜的
  不一样——这个接口的返回我们没实测过）。这种页**不算数、不留**：它不是「翻到底了」，
  更不是「没搜到」。第 1 页就这样，整轮立刻停，只花这一次的钱，命令的退出码不是 0，
  报告最上面有一句 ⚠ 并列出那几页条目的类型和键名（只有名字）。这时候别看下面的数，
  先找人改代码；改好再跑同一条命令，那一页会重新拿（要再花一次的钱）。
- **余额对账**：见上一节。

### 看完怎么定（设计时定的三条）

- 3 天内的帖子，综合排序 3 页里搜到的**不到五分之一**：综合排序的名次对小号不是个可用的信号，
  改查「最新」排序（收没收录），或者不查第 3 天。
- 同样的搜索两次名次**差出一页以上**：表里只写档位，不写具体名次。
- 翻到第几页搜到的比例就不再涨：以后就查到第几页。

## 六、要知道的几件事

- **名次是供应商那一刻看到的**，不是某个读者看到的。它用哪个地区、什么账号去搜，对方没说。
- **只查小红书。** 抖音这次不查。
- **只走 TikHub。** 备用那家有搜索接口，但我们一次都没调过。
- 进度文件里有搜索结果里别人笔记的 ID（只有 ID 和名次），所以它只放在本机、不许放进仓库。
  试跑结束、报告留好之后可以把 `~/.linkcheck/search-trial` 整个删掉。
- 报告可以直接转给别人看；进度文件 `state.json` 不要外传。

## 七、这次没做的

试跑有了结论再定，现在都没有：机器往表里写结果的那几列（搜索可见 / 搜索排名 /
搜索检查时间 / 搜索明细）、每天自动查一次、面板上的开关和日报里的一行、每张表的默认关键词。
