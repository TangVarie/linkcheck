# 多维表格建表说明（OKMAN 系列表对齐版）

列名必须与 `xhsearch/config.py` 里的 `FieldNames` **逐字相同**（含空格、括号全半角、
英文点号——`实时数据.评论数` 里那个点也是列名的一部分）。飞书开放平台按**字段名**
寻址，对不上会直接报 `1254045 FieldNameNotFound`。

默认映射按 OKMAN 系列表的实际结构对齐（以「OKMAN第一期」为准）。你们已有的
业务列（素人编号、方向、文案、随贴评论、曝光量……）机器**完全不读不写**，
随便加减。下面只列机器要用的列。

> 表里还没建的机器列会被**自动跳过**（不会写坏表、不会整批回滚），跳过的列名
> 会打在运行日志里；`python3 cli.py doctor` 也会提前列出缺哪些。

---

## 一、人工维护的列

| 列名 | 字段类型 | 必填 | 说明 |
|---|---|:---:|---|
| `反馈链接` | **单行文本** | ✅ | 原样粘贴分享文案或链接（`xhslink.com` 短链直接可用）。**不要用超链接字段**——会规范化掉小红书链接里的 token |
| `发布时间` | 日期 | 建议 | 分层刷新靠它分档。留空则每轮都刷（宁可多花一毛，也别让一行永远不更新） |
| `蓝词字段` | 多选 或 单行文本 | 选填 | **一组蓝词**（如 `西地那非口溶膜`、`艾时达口溶膜`、`cGMP因子`）。任一词出现在第一页任一条评论里即算命中。多选列直接建选项；文本列用 顿号/逗号/分号 分隔多个词。匹配不区分大小写（`cGMP`/`cgmp` 都能中） |
| `是否巡查` | 复选框 | ✅ | 勾上才刷新；取消勾选即完全停止。结案后勾掉，永久止损 |
| `排队刷新` | 复选框 | ✅ | **手动触发入口**。勾上 → 后台处理 → 自动清掉。勾消失就是"已完成"。可拖拽批量勾，90 秒内连勾多次只算一次 |

> 为什么手动入口用复选框而不是按钮字段：复选框走后台轮询，**一次飞书自动化
> 配额都不消耗**，而且能拖拽批量勾 50 行。按钮每点一次消耗一次租户级配额。

## 二、机器写入的列

| 列名 | 字段类型 | 说明 |
|---|---|---|
| `平台` | 单选 | 选项：`小红书` / `抖音`。机器按链接域名识别 |
| `实时数据.评论数` | **数字** | 含回复的总评论数 |
| `上次评论数` | 数字 | 写新值前先搬过来，公式列算增量用。建议隐藏 |
| `点赞数` | 数字 | 小红书发布 7 天内补 detail 时才有 |
| `上次点赞数` | 数字 | 与评论数的搬移完全对称，作参考。建议隐藏 |
| `收藏数` | 数字 | 同点赞数 |
| `上次收藏数` | 数字 | 同上次点赞数 |
| `置顶评论` | 多行文本 | **实际置顶那条的内容**。帖子是我们自己发的，置顶必为我方——所以只展示内容、不做匹配。抖音行固定写「—（抖音不支持置顶监控）」 |
| `评论状态` | **多选** | 人机共用。机器只管置顶三个值（见下）；`显示评论`/`待评论`/`没有显示`/`风控` 等人工值机器读得到但**永远不碰** |
| `评论区快照` | 多行文本 | 综合排序前 8 条评论 |
| `蓝词命中` | 多行文本 | `✅ 命中「艾时达口溶膜」：<那条评论前 60 字>` 或 `❌ 未命中（第一页 N 条评论）`。**没填蓝词的行不碰这一列** |
| `流量状态` | **多选** | 人机共用，见下。`无水花`/`爆帖预备` 等人工值机器不碰 |
| `巡查状态` | 单选 | 选项：`正常` / `疑似受限` / `已失效` / `刷新失败` / `跳过` / `冷却跳过` |
| `诊断信息` | 多行文本 | 人话解释 + 上游原始错误。看不懂也能截图给 IT（带 request_id） |
| `最近检查时间` | 日期 | 分层刷新的依据。失败也会更新——`巡查状态` 已说明数据新旧 |
| `已确认存活` | 复选框 | 本轮成功取到数 → 勾上；连续两次确认失效 → 取消。其余情况不动 |
| `连续失败次数` | 数字 | 两击定罪的计数器（只计「取不到内容」，网络失败不计）。建议隐藏 |

### `评论状态`（多选，人机共用）

机器只碰这三个值，**必须先建好选项**：

| 值 | 什么时候写 |
|---|---|
| `置顶成功` | 本轮有置顶评论（自家帖子，有置顶即我方置顶在） |
| `置顶掉了` | **之前有过**，现在没了 |
| `没有置顶` | 从来没有过，现在也没有 |

三个值互斥，每轮只留一个。「掉了」和「从来没有」的区别全看这一行的历史；
掉了之后一直没恢复会保持「置顶掉了」，不会退回「没有置顶」。
抖音行完全不碰这一列（接口没有置顶字段）。

### `流量状态`（多选）

机器只碰这五个词，**必须先建好选项**：

| 标签 | 什么时候打 |
|---|---|
| `评估中` | 评论数 ≥ 20 |
| `爆贴` | 评论数 ≥ 50 |
| `大爆` | 评论数 ≥ 100 |
| `风控中` | 评论数腰斩 / 发布 48h 仍零评论 / 连续两次取不到内容 |
| `已失效` | 连续两次确认取不到（上游权威确认「已删除」第一次就判） |

**热度三档互斥且只升不降**；`风控中`/`已失效` 每轮重算，恢复自动摘掉。
判定**只基于评论数**——点赞、收藏只是参考列，不参与打标签。
`无水花`、`爆帖预备` 以及未来新增的任何选项机器零权限。

## 三、可选：增量公式列

| 公式列 | 公式 |
|---|---|
| `评论增量` | `实时数据.评论数 - 上次评论数` |
| `点赞增量` | `点赞数 - 上次点赞数` |

飞书自己算，零写入成本。`评论增量` 是"今天谁涨得最猛"的排序列。

---

## 四、应用权限设置（最容易卡住的一步）

1. 飞书开放平台建**企业自建应用**，开权限 `bitable:app`，**发布版本并等审批通过**。
2. 打开目标多维表格 → 右上角 `…` → `更多` → **`添加文档应用`** → 搜应用名 → 添加，权限「可编辑」。
3. **如果这张表开了「高级权限」**：还要在高级权限里给应用 **「可管理」**。
   ⚠️ 漏这一步的表现是**读到空结果而不是报错**。
4. `python3 cli.py doctor` 全绿（含列名检查）再开跑。

## 五、推荐视图

| 视图 | 筛选条件 | 给谁看 |
|---|---|---|
| 🔥 爆贴榜 | `流量状态` 含 爆贴/大爆，按 `评论增量` 降序 | 运营 |
| ⚠️ 今日待办 | `巡查状态` ∈ {疑似受限, 已失效, 刷新失败} 或 `流量状态` 含 风控中 | 运营 |

| ⚠️ 置顶掉了 | `评论状态` 含 置顶掉了 | 投放 |
| ⚙️ 待刷新队列 | `排队刷新` 已勾 且 `是否巡查` 已勾 | 系统 |
